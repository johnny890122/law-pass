# 2026-10-21 — Dark mode, stored per learner

**LP ids:** LP-0004-09

Learners study at night on their phones. They can now switch the app to a
dark theme, and the choice follows them to every browser they sign in from.
The user picked the `teal-ink` palette from three derived variants
([DECISION](../../artifacts/LP-0004-09-dark-mode/DECISION.md)). This landing
builds it per the approved [PRD](../prd/LP-0004-09-dark-mode.md). Rules now
live in [`docs/modules/ui/index.md`](../modules/ui/index.md) § Themes and in
[`data-model.md`](../modules/db/data-model.md) § `user_ui_flags`.

| Area | Was | Now |
| --- | --- | --- |
| Themes | Light only. | Light, the default, and dark. The OS setting is ignored. |
| Shell | Logo, select, 中/EN, and logout in the top bar. | A theme toggle sits beside 中/EN: a moon in light and a sun in dark, labeled 「深色模式」 with `aria-pressed`. It shows at every width and for every law type. In the sidebar it shares 中/EN's row. |
| Switching | — | A click saves the other theme (`PUT /api/ui-flags/theme`) and reloads the page. A failed save shows `apiCall`'s toast and leaves the page as it was. |
| Storage | No per-user UI preference. 中/EN lives in `localStorage` on one browser. | A new `user_ui_flags` collection, one document per user (`user_id`, `theme`, `updated_at`), unique on `user_id`. A missing document means light. |
| First paint | — | The server writes `data-theme` on `<html>` from the stored flag before any stylesheet loads, so a dark learner never sees a light frame. |
| Tokens | One light `:root` block. | `tokens.css` adds `color-scheme` and a `:root[data-theme="dark"]` block. Each value is marked `derived:` with its reason and its contrast ratios. `style.css`, the templates, and JS still read the same names. |
| Fills | White labels on teal and magenta. | In dark, the labels on filled buttons and the 選擇題 and 簡答題 badges turn dark (the ground), since those fills turn light. |
| Charts | Teal bars and a neutral line. | The same roles in the active theme's colors, read on load. A theme switch reloads, so they always match. |
| Login | Light. | Still light. It has no user, and its Google and LINE buttons keep their owners' light values. |

Checked in the running app on a throwaway database (`lp_0004_09`):

- Switching wrote one `user_ui_flags` document, and a reload stayed dark.
- A second browser context, with a freshly minted session for the same user,
  received `data-theme="dark"` in the raw HTML ahead of `tokens.css`, with no
  script in `<head>`.
- Logging out there showed a light login page.
- `/progress` drew `#2ca9b1` bars in dark and `#00727a` in light.
- Every page passed the `docs/modules/ui/index.md` check at 390x844,
  768x1024, and 1440x900, in both themes, with no console errors. The
  screenshots were looked at.

Real Google and LINE sign-in cannot complete against a local server. "Signing
in again" was simulated with a new session cookie. `pytest` (131) and
`flake8` pass.

## Implementation notes

- **How the dark values are made.** Each role keeps its light hue at 0.6×
  saturation, so nothing glows. It is lightened until it has the contrast on
  the dark panel that its light value has on white. A role with a tint is
  also lightened until it clears 4.5:1 on that tint, which moved only success.
  The three variants differ only in the ground and in how panels separate
  from it.
- **One read per page.** A context processor on `frontend_bp` does one
  indexed `find_one` per render. It was picked over a copy in the session so
  a browser that is already signed in picks up a switch on its next page.
- **401, not a redirect.** The save route checks the session itself, as
  `/auth/current` does. `login_required` would redirect, and `fetch` would
  follow that silently.
- **`.shell-tools`** wraps 中/EN and the toggle. The sidebar's
  `.lang-toggle { align-self: flex-start; }` was removed, since the wrapper
  row places both.
- **`PER_USER`** in the LP-0002-01 cleanup migration gains `user_ui_flags`,
  so deleting a username-only user also deletes their flags.
- **MongoDB locally** now runs as `mongo:7` in Docker (`law-pass-mongo` on
  127.0.0.1:27017), the image CI uses.
